# Artix-7 5GBASE-R benches

`bench/ac701_5g.py` and `bench/acorn_baseboard_mini_5g.py` connect the native
`A7_GTP_5G_BASER` PHY to a 32-bit Etherbone core. They adapt the board examples
from the [#217 follow-up branch](https://github.com/quadraturecat/liteeth/commit/391d9679e2e492cd51576313fe91367d21e061d4)
to the current PCS/PMA split, MAC queues, PHY diagnostics and LiteX SFP API.
The updated benches require hardware validation on their respective boards.

The protocol core runs at 100 MHz in `sys`. MACCore supplies complete-frame TX
buffering and whole-frame RX drops on congestion, with its usual width conversion
and CDC. A 32-bit 100 MHz core cannot sustain every 5G traffic pattern; these are
bring-up/Etherbone examples. No extra FIFO wrapper or board-specific PCS is used.

## Reference clocks

The GTP line rate is 5.15625 Gb/s. With `TXOUT_DIV = RXOUT_DIV = 1`, its PLL VCO
must be 2.578125 GHz:

```text
VCO = refclk * fbdiv * fbdiv_45 / refclk_div
line rate = 2 * VCO
```

The following reference/divider combinations use `refclk_div=1`:

| Reference (MHz) | `fbdiv` | `fbdiv_45` | Example |
| ---: | ---: | ---: | --- |
| 103.125 | 5 | 5 | AC701 Si5324 output |
| 128.90625 | 4 | 5 | External reference |
| 161.1328125 | 4 | 4 | External reference |
| 171.875 | 3 | 5 | Acorn fabric PLL |

125 MHz and 156.25 MHz cannot produce this line rate with the GTP's integer
dividers. Changing only the PHY's `refclk_freq` argument does not program a PLL:
the board must supply the actual clock and matching `QPLLSettings`. Pass the
same frequency to the PHY so its calibration dividers are correct. The historical
LiteEth `QPLL` helper instantiates `GTPE2_COMMON`, which contains the two GTP PLLs.
Use `refclksel=0b001` for MGTREFCLK0 or `0b111` for GTGREFCLK0.

The native 32-bit gearbox needs TX/RXUSRCLK at 322.265625 MHz and USRCLK2 at
161.1328125 MHz. Each PMA MMCM supplies both clocks. There are 16 complete
64b/66b blocks per 33 USRCLK2 cycles, with the TX pause at sequence 31. The
PHY's clock-enable signals qualify block transfers; no gated PCS clock or
multicycle exception is needed. See [UG482](https://docs.amd.com/v/u/en-US/ug482_7Series_GTP_Transceivers),
particularly the PLL, user-clock and 64b/66b gearbox sections.

### AC701

The bench forwards the default 156.25 MHz Si570 clock through FPGA pins D23/D24
to the Si5324. BIOS programs the Si5324 to 103.125 MHz through I2C mux channel 7
(`0x74`, device `0x68`). Its dividers are N31=1000, N2=31680 and N1=48, giving
a 4.95 GHz oscillator and 103.125 MHz output. The sequence assumes the Si5324's
power-on defaults; power-cycle the board after using a different clock setup.

U3 selects its Si5324 input (`SFP_MGT_CLK_SEL=01`) for MGTREFCLK0. The bench
releases the I2C mux and Si5324 resets and drives R18 low to enable transmission.
Despite its `sfp_tx_disable_n` platform name, R18 is active-high TX_DISABLE.
Board wiring and SFP jumpers are described in
[UG952](https://docs.amd.com/v/u/en-US/ug952-ac701-a7-eval-bd).

### Acorn Baseboard Mini

The bench uses SFP0 and derives an exact 171.875 MHz clock from the 200 MHz
oscillator using a fabric PLL. This feeds GTGREFCLK0. It retains the original
bench's REQP-49 severity override for that reference path; the override does not
establish jitter compliance. Validate clock quality and link stability on the
actual board. Prefer a dedicated MGT reference on designs that provide one.

RX polarity is inverted; the Acorn and baseboard TX inversions cancel. The
default variant is CLE-215+. The management bus is the platform's `sfp_i2c`.

## Build and SFP setup

Use current LiteX, LiteICLink, LiteX-Boards and the VexRiscv CPU data package.
The BIOS needs LiteX's per-cage SFP support from
[LiteX #2563](https://github.com/enjoy-digital/litex/pull/2563).
From the LiteEth repository root:

```sh
PYTHONPATH=. python3 bench/ac701_5g.py --build --output-dir build/ac701_5g --csr-csv build/ac701_5g/csr.csv
PYTHONPATH=. python3 bench/acorn_baseboard_mini_5g.py --build --output-dir build/acorn_5g --csr-csv build/acorn_5g/csr.csv
```

Add `--load` to load the bitstream. To generate RTL without compiling software
or running Vivado, omit `--build` and add `--no-compile-software`. Use `--eth-ip`
to change the default `192.168.1.50` address.

The scripts expose LiteX's standard Vivado directive options. AC701 defaults to
Explore placement/routing and physical fanout optimization for the TX gearbox
enable path. Recheck routed timing when changing the system clock or build options.

Both benches declare `SFP_0_I2C` and `SFP_0_HOST_MODE="5GBASER"`; AC701 also
declares mux address `0x74`, channel 4. BIOS initializes the clock first and
then probes/configures the SFP using LiteX's existing software. The default
requests a **5GBASE-R host interface**, distinct from 5GBASE-T on the cable or
5000BASE-X. Module support depends on its PHY and management firmware, not its
label. A module negotiating 5GBASE-T may still require a 10GBASE-R host.

For an already configured module or fixed-rate peer, `--sfp-host-mode AUTO`
leaves its configuration alone. On the BIOS console, `sfp` probes the cage and
`sfp 0 5GBASER` reapplies the host mode after a module power cycle or replacement.
AC701 uses its serial console; Acorn uses the crossover UART via JTAGBone.
With the JTAG server running, open the latter with
`litex_term crossover --csr-csv build/acorn_5g/csr.csv`. Its buffered console
allows BIOS initialization to finish before the terminal is connected.

After BIOS clock/SFP initialization, reset the PHY through JTAGBone before
testing Ethernet. In particular, AC701's reference clock changes after FPGA
configuration. Start `litex_server --jtag --jtag-config openocd_xc7_ft2232.cfg`
for an FT2232 adapter; select the matching OpenOCD configuration for other
adapters. Keep TCK at or below the bench's 20 MHz timing constraint. Then,
using the board's generated CSR file:

```python
import time
from litex import RemoteClient

wb = RemoteClient(csr_csv="build/ac701_5g/csr.csv")
wb.open()
try:
    wb.regs.ethphy_reset.write(1)
    time.sleep(0.01)
    wb.regs.ethphy_reset.write(0)
    time.sleep(0.1)
    print(hex(wb.regs.ethphy_status.read()))
finally:
    wb.close()
```

The standard `ethphy_control`, `ethphy_status` and `ethphy_rx_prbs_errors` CSRs
provide loopback, block lock, BER and PRBS diagnostics. See
[PHY diagnostics](phy_portability.md#reading-base-r-diagnostics) for coherent
counter reads. `link_up` is qualified receive PCS status, not proof of a working
bidirectional peer. Check traffic and loss after reset and cable reconnection.

## Regression checks

```sh
python3 -m pytest -q test/test_a7_baser.py test/test_a7_baser_bench.py
```

The tests exercise the production PMA fabric's startup gating, 33-cycle cadence,
upper/lower word ordering, receive gaps and pairing, bitslip holdoff, and reset
recovery. They also check both PLL selections, the MMCM clock ratio, reference
calibration, board RTL generation, standard CSRs and SFP configuration. Simulation
supplies GT outputs and MMCM lock; it does not model serialization, analog lock,
clock jitter or the Si5324/SFP devices. Timing and real-peer testing remain board
validation tasks.
