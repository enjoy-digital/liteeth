# 100G hardware MAC

LiteEth provides a buffered AXI frame adapter, an UltraScale+ CMAC wrapper and
simulation/synthesis benches. The CMAC configuration is CAUI-4 NRZ without FEC,
for a matching no-FEC module and peer. Hardware validation is pending, and the
UDP/IP core does not sustain 100G minimum-frame traffic. See the separate
[native PCS reference](100g_pcs.md) for lane modelling and FEC requirements.

## Frame adapter

`liteeth.mac.axis.LiteEthMACAXIStream` connects AXI to the usual PHY-facing
`data/be/error/last` stream. Frames start at destination MAC and omit FCS.
Byte lane zero is first; `be` maps to `tkeep`. Non-final masks must be full;
final masks must be nonempty and contiguous from lane zero.

TX uses the existing padding inserter and `PacketFIFO` to commit a complete
frame of at least 60 bytes before transmission. AXI supports backpressure;
input errors accumulate into final `tuser`. Producers must terminate frames
within the configured MTU. The hardware MAC supplies FCS, preamble and IFG.
Adapter capabilities disable the corresponding soft-MAC stages and automatic
packet queues; explicit `with_store_and_forward=True` adds redundant queues.

RX has no backpressure. `PacketDropFIFO` discards whole frames on overflow,
AXI errors, malformed masks, runts or oversize. The 32-bit wrapping counters
`rx_packets`, `rx_drops` and `rx_bad_frames` belong to `eth_rx`. Bad frames are
a subset of drops; counters cover only frames delivered by the hardware MAC.
Use coherent CDC snapshots when exposing them to software.

The parent owns `eth_tx`/`eth_rx` clocks and resets. `LiteEthUDPIPCore` supplies
its usual CDC and width conversion. Reset connected domains together when
flushing the pipeline. The benchmark tests coordinated reset; it does not test
independent FIFO-side resets.

## UltraScale+ CMAC

Import `USP_CMAC_100G` from `liteeth.phy.serial.baser.wrappers.usp_cmac`.
The generated IP includes GTs and shared clock/reset logic:

| Setting | Value |
| --- | --- |
| IP name | `liteeth_cmac` by default |
| Lanes | Four differential GT lanes |
| Reference clock | 161.1328125 MHz |
| Initialization/DRP clock | Free-running 100 MHz |
| TX and RX AXI clock | CMAC TX user clock, 322.265625 MHz |
| Maximum frame | 9022 bytes including FCS |

The target sources `bench/cmac_100g.tcl` after setting `cmac_name`, `cmac_site`
and `cmac_gt_group`. It owns pins, reference-buffer LOC, CMAC/GT placement,
constraints, module management and peer configuration. Keep the adapter MTU
consistent with the IP. This wrapper has no standalone-generator entry.

Reception is enabled; TX sends remote fault and retains queued frames until
lanes align. `link_up` is synchronized to `sys`; other status signals retain
their vendor domain. AN, link training, RS-FEC, PTP and pause control are disabled.
The clock/reset/AXI contracts follow AMD PG203:
[RX clock](https://docs.amd.com/r/en-US/pg203-cmac-usplus/RX-CLK),
[resets](https://docs.amd.com/r/en-US/pg203-cmac-usplus/Resets),
[AXI](https://docs.amd.com/r/en-US/pg203-cmac-usplus/User-Side-AXI4-Stream-Interface).

Generate and synthesize from the repository root:

```sh
PYTHONPATH=. python3 bench/cmac_100g.py --output-dir build/cmac_100g
cd build/cmac_100g
vivado -mode batch -source build.tcl
```

Part, site and GT group are configurable. Vivado 2024.1 synthesis on the default
`xcvu3p-ffvc1517-2-e` resolves one CMACE4, four GTYE4_CHANNEL and one GTYE4_COMMON.
Board pin/reference-buffer placement remains unconstrained in this OOC build.

## Simulation and timing

Run the Verilator traffic benchmark from the repository root:

```sh
PYTHONPATH=. python3 bench/mac_100g.py --profile standard --packets 128
PYTHONPATH=. python3 bench/mac_100g.py --profile minimum --packets 128
PYTHONPATH=. python3 bench/mac_100g.py --profile mixed --packets 64 --stall-cycles 200 --error-every 13 --reset
```

The full UDP/IP/adapter path uses finite queues and independent clocks. RX never
waits for ready. Python builds reference packets; the RTL scoreboard checks
bytes, metadata, masks, ordering, stall stability, TX underrun and loss accounting.
`--rate` sets offered RX rate only; TX acceptance is capped by a 100G wire-time
model. Both account for preamble, FCS and IFG, without modelling CMAC internal
scheduling or the PCS/GTs.

JSON results contain packet rates, TX wire-equivalent and RX payload rates,
loss, errors and maximum latency from RX frame completion. Run enough packets
to expose sustained overload: short runs can fit in the queues. Minimum,
standard and jumbo profiles use 18-, 1472- and 8972-byte UDP payloads.

Generate a routed timing build from the repository root:

```sh
PYTHONPATH=. python3 -m bench.mac_100g_timing --output-dir build/mac_100g_timing
cd build/mac_100g_timing
vivado -mode batch -source timing.tcl
```

The portable adapter/CDC/UDP path at 250 MHz system / 322.265625 MHz MAC clocks
reported +0.067 ns setup and +0.043 ns hold slack in Vivado 2024.1 on the default
part, using 4463 LUTs, 8576 registers and 17.5 BRAM tiles. This is internal
register timing: CMAC/GT routing and board I/O delays are excluded. The small
margin and asynchronous clock-group exceptions require target timing/CDC review.

CI covers adapter, padding, wrapper elaboration and traffic regressions. Vivado
checks are local. Hardware testing must cover the module/peer, clocks, resets,
lane wiring, error recovery, wire framing and sustained traffic.
